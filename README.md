# Farstar Tunnel

پنل فارسی و خودمیزبان برای اتصال دو سرور اوبونتو. نرم‌افزار یکسان روی هر دو نصب می‌شود؛ یکی **ورودی** و دیگری **مقصد** است. سرویس‌های موجود روی مقصد، بدون جابه‌جایی یا تغییر تنظیماتشان، از پورت‌های انتخابی ورودی قابل دسترسی می‌شوند.

```text
کاربر → IP سرور ورودی:2083 → تونل رمزگذاری‌شده → سرور مقصد:127.0.0.1:443
              پنل ورودی                         پنل مقصد
              ساخت و مدیریت                     همگام‌سازی خودکار
```

الهام از تجربهٔ کاربری [Phantom Tunnel](https://github.com/webwizards-team/Phantom-Tunnel)؛ پیاده‌سازی مستقل. هستهٔ انتقال [FRP 0.71.0](https://github.com/fatedier/frp/releases/tag/v0.71.0) است و کد پروژهٔ مرجع کپی نشده است.

## نصب آسان روی اوبونتو

پیش‌نیاز: Ubuntu **22.04 / 24.04 یا جدیدتر**، Python 3.10+، systemd و دسترسی sudo. معماری x86_64 و ARM64 پشتیبانی می‌شود. هنگام نصب، دسترسی به PyPI و GitHub برای دریافت بسته‌ها لازم است.

روی **هر دو سرور** همین یک دستور را اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/farstar-team/farstar_tunnel/main/install.sh | sudo bash
```

نصب به ترتیب این موارد را می‌پرسد:

- **۱ / سرور ورودی**: سروری که کاربران به IP آن وصل می‌شوند؛ معمولاً سرور ایران.
- **۲ / سرور مقصد**: سروری که سرویس اصلی روی آن اجراست؛ معمولاً سرور خارج.
- سپس **IP عمومی یا دامنهٔ همین سرور** را وارد کنید، بدون `https://` و بدون پورت.
- **پورت پنل وب**؛ پیش‌فرض 8443 است و هر پورت آزاد از 1024 تا 65535 قابل انتخاب است.
- **نام کاربری پنل**؛ پیش‌فرض `admin` است و می‌توانید آن را تغییر دهید.
- **رمز دلخواه و تکرار آن**؛ ۱۲ تا ۱۲۸ کاراکتر. هنگام تایپ نمایش داده نمی‌شود.

در پایان، نصب آدرس HTTPS پنل را نشان می‌دهد. با همان نام کاربری و رمز وارد شوید. **رمز پیش‌فرض وجود ندارد.** هر سرور حساب مدیر جداگانه دارد. رمز در آرگومان‌های پردازش، خروجی نصب یا فایل متنی ذخیره نمی‌شود؛ فقط هش scrypt آن نگهداری می‌شود.

برای تعیین گزینه‌ها در دستور نصب؛ رمز همچنان مخفی از ترمینال پرسیده می‌شود:

```bash
# روی ورودی؛ INGRESS_IP را با IP همین سرور عوض کنید.
curl -fsSL https://raw.githubusercontent.com/farstar-team/farstar_tunnel/main/install.sh | sudo bash -s -- --role hub --host INGRESS_IP --name 'سرور ورودی' --port 8443 --username myadmin

# روی مقصد؛ DESTINATION_IP را با IP همین سرور عوض کنید.
curl -fsSL https://raw.githubusercontent.com/farstar-team/farstar_tunnel/main/install.sh | sudo bash -s -- --role connector --host DESTINATION_IP --name 'سرور مقصد' --port 8443 --username myadmin
```

پنل پیش‌فرض: `https://IP:8443`. اگر 8443 اشغال است، از `--port` استفاده کنید. نصب روی نسخهٔ موجود یا دادهٔ قبلی انجام نمی‌شود تا تنظیمات قبلی بازنویسی نشوند.

اگر فایل‌های پروژه را با Git یا بستهٔ سورس دریافت کرده‌اید، `sudo bash install.sh` نیز کار می‌کند. برای اتوماسیون، نصب محلی گزینهٔ `--password-stdin` دارد: یک خط رمز از ورودی استاندارد می‌خواند؛ سایر گزینه‌ها باید کامل باشند. رمز را در دستور، تاریخچهٔ شل یا گزینهٔ `--password` ننویسید. راهنمای نصب داخل `/opt/farstar-tunnel/README.md` نیز ذخیره می‌شود.

### تغییر پورت، نام کاربری و رمز بعد از نصب

```bash
# تغییر نام کاربری و رمز؛ رمز به شکل مخفی پرسیده می‌شود.
sudo -u farstar-tunnel /opt/farstar-tunnel/venv/bin/farstar configure-panel --username myadmin --prompt-password

# تغییر پورت پنل به یک پورت آزاد؛ فقط سرویس خود برنامه ری‌استارت می‌شود.
sudo -u farstar-tunnel /opt/farstar-tunnel/venv/bin/farstar configure-panel --port 9443
sudo systemctl restart farstar-tunnel.service
```

هر گزینه را می‌توانید جداگانه استفاده کنید. تغییر نام کاربری یا رمز، نشست‌های ورود قبلی را باطل می‌کند. ری‌استارت سرویس، تونل‌های همین برنامه را برای مدتی کوتاه قطع می‌کند.

اگر **پورت پنل ورودی** را بعد از اتصال سرورها تغییر دادید، روی **هر سرور مقصد متصل** نیز دستور زیر را با همان پورت جدید اجرا کنید تا هماهنگی دو پنل ادامه پیدا کند؛ اتصال‌ها، توکن‌ها و تنظیمات تونل نگهداری می‌شوند:

```bash
sudo -u farstar-tunnel /opt/farstar-tunnel/venv/bin/farstar configure-upstream --port 9443
```

پورت جدید باید در فایروال ارائه‌دهنده مجاز باشد. برنامه فایروال را خودکار تغییر نمی‌دهد.

### گواهی HTTPS

برای هر نصب یک CA مستقل و گواهی ساخته می‌شود. مرورگر ابتدا هشدار گواهی خصوصی نشان می‌دهد. **اثر انگشت SHA-256** گواهی در خروجی نصب هست؛ قبل از پذیرش در مرورگر آن را تطبیق دهید. می‌توانید CA همان نصب را از `/var/lib/farstar-tunnel/pki/ca.crt` به دستگاه مدیریتی خود اضافه کنید. کلید خصوصی CA را منتقل نکنید.

هویت سرور بین دو پنل و داخل تونل با همین CA و نام سرور بررسی می‌شود؛ بررسی TLS غیرفعال نمی‌شود.

## اتصال دو سرور از پنل

۱. در **پنل ورودی → سرورها → اتصال سرور**، نامی مثل «سرور آلمان» بدهید و کد بسازید.

۲. در **پنل مقصد → اتصال به سرور ورودی**، کد را وارد کنید. کد فقط **یک بار** و تا **۱۰ دقیقه** معتبر است. کد حاوی مجوز اتصال است؛ آن را خصوصی نگه دارید.

۳. به پنل ورودی برگردید، **تونل جدید** را بزنید و مقصد را انتخاب کنید.

مثال برای سرویسی که از قبل روی پورت 443 مقصد اجرا می‌شود:

| گزینه | مقدار نمونه |
|---|---|
| نام تونل | ارتباط اصلی |
| حامل ارتباط | خودکار |
| پورت کنترل | 7443 |
| نوع مسیر | TCP |
| پورت ورودی | 2083 |
| پورت مقصد | 443 |

بعد از اتصال، `IP-ورودی:2083` به `127.0.0.1:443` سرور مقصد می‌رسد. لازم نیست سرویس مقصد را ری‌استارت یا تنظیماتش را عوض کنید. پورت مقصد باید از خود سرور مقصد قابل دسترسی باشد؛ مقصدهای خارج از loopback از API پذیرفته نمی‌شوند.

### پورت‌های لازم

**خود برنامه فایروال را تغییر نمی‌دهد.** در فایروال سیستم یا پنل ارائه‌دهنده، فقط پورت‌های انتخابی را باز کنید:

| سرور | پورت | دسترسی موردنیاز |
|---|---|---|
| ورودی | TCP 8443 یا پورت پنل شما | مدیر و IP سرور مقصد |
| مقصد | TCP 8443 یا پورت پنل شما | مدیر |
| ورودی | TCP پورت کنترل هر تونل | IP سرور مقصد |
| ورودی | UDP همان پورت کنترل | برای حالت خودکار / QUIC |
| ورودی | TCP / UDP پورت ورودی هر مسیر | کاربران سرویس |
| مقصد | پورت سرویس محلی | تنها loopback کافی است |

روی مقصد، تونل اتصال خروجی برقرار می‌کند و نیازی به پورت ورودی اضافی برای FRP نیست.

## قابلیت‌های پیاده‌سازی‌شده

- پنل فارسی RTL، واکنش‌گرا، بدون CDN، فونت یا اسکریپت خارجی.
- TCP/TLS، QUIC، WSS و انتقال سرویس‌های TCP و UDP.
- حالت خودکار: QUIC، سپس بعد از ۲۰ ثانیه عدم اتصال، TCP/TLS. پس از تغییر به TCP، تا ویرایش یا راه‌اندازی دوبارهٔ هسته روی TCP باقی می‌ماند؛ سوییچ مداوم و قطع ارتباط ایجاد نمی‌کند.
- TCP multiplexing، heartbeat، اتصال مجدد و backoff محدود برای پردازش خراب.
- یک پردازش FRP جدا برای هر تونل؛ توقف یا ویرایش تونل به بقیهٔ تونل‌ها فرمان ری‌استارت نمی‌دهد.
- بررسی تداخل پورت قبل از اجرا، `frp verify` روی تنظیمات نامزد و بازگشت به تنظیمات قبلی اگر شروع ناموفق باشد.
- همگام‌سازی مقصد هر سه ثانیه؛ ذخیرهٔ آخرین تنظیمات تأییدشده برای شروع مجدد.
- قطعی API مدیریتی، تونل‌های برقرار را متوقف نمی‌کند. لغو دسترسی مقصد روی ورودی، پردازش‌های متعلق به آن را فوراً متوقف می‌کند و مقصد در همگام‌سازی بعدی آن‌ها را می‌بندد.
- چند مسیر پورت برای هر تونل، سقف پهنای باند **هر مسیر**، فشرده‌سازی اختیاری و بررسی سلامت TCP مقصد.
- آمار واقعی هسته، اتصالات، مصرف منابع محلی، گزارش رویدادها و ۱۰۰ خط آخر هر هسته.
- حساب مدیر با scrypt، نشست HttpOnly / Secure / SameSite، محافظت CSRF، کنترل Origin و محدودیت تلاش ورود.
- توکن اختصاصی هر تونل؛ احراز هویت heartbeat و work connection؛ whitelist دقیق پورت‌های مجاز.
- خروجی JSON تنظیمات بدون توکن، حساب، کلید و نشست.

### جداسازی از سرویس‌های دیگر

سرویس با **کاربر اختصاصی `farstar-tunnel`** و بدون capability اجرا می‌شود. `systemd` فایل‌سیستم را به جز پوشهٔ داده فقط‌خواندنی می‌کند، دسترسی به home و تنظیمات kernel را می‌بندد و منابع کل پنل و تمام هسته‌هایش را محدود می‌کند:

- RAM: سقف 512 MB؛ حد نرم 384 MB.
- CPU: حداکثر معادل یک هسته؛ اولویت کمتر از سرویس‌های معمول.
- سقف 256 task و 16384 فایل باز.
- حداکثر ۱۶ تونل و ۱۶ مسیر در هر تونل.
- پورت‌های عمومی زیر 1024 پذیرفته نمی‌شوند؛ پورت مقصد محلی می‌تواند 443، 80 یا هر پورت معتبر دیگری باشد.

هیچ دستور `iptables`، `ufw`، `nft`، `sysctl`، تغییر route، حذف سرویس یا تغییر SSH/nginx اجرا نمی‌شود. فقط وابستگی `python3-venv` در صورت نبودن، با `--no-upgrade` نصب می‌شود؛ کتابخانه‌های برنامه داخل venv اختصاصی هستند. دریافت هسته از انتشار رسمی FRP با SHA-256 ثابت تأیید می‌شود.

مصرف شبکه همچنان مشترک با سایر سرویس‌های سرور است؛ برای سرور پرترافیک از سقف پهنای باند مسیرها استفاده کنید. این محدودیت و جداسازی، ریسک را کاهش می‌دهند؛ تضمین ظرفیت یا سرعت روی هر شبکه نیستند.

### جزئیات WSS

FRP الزام TLS داخلی را روی WebSocket پس از پایان TLS بیرونی نمی‌پذیرد. برای WSS، پنل یک relay **فقط TLS** روی پورت کنترل می‌گذارد و WebSocket خام FRP فقط روی `127.0.0.1` قابل دسترسی است. relay دارای محدودیت ۶۴ ارتباط کنترل به ازای هر تونل و بافر 64 KiB است. پورت‌های سرویس‌ها همچنان توسط FRP انتقال می‌یابند. برای کارایی مستقیم‌تر، TCP/TLS یا QUIC را انتخاب کنید.

### دقت آمار و تغییر تنظیمات

FRP حجم TCP را پس از بسته‌شدن ارتباط ثبت می‌کند؛ نمودار، نرخ تغییر همین شمارنده‌ها را نشان می‌دهد و تخمین لحظه‌ای ترافیک یک اتصال طولانی نیست. آمار امروز طبق ساعت هستهٔ سرور است و پس از ری‌استارت FRP صفر می‌شود. مقصد شمارندهٔ حجم مستقل ندارد؛ حجم و تعداد اتصال روی ورودی دیده می‌شود. تاریخچهٔ نمودار در حافظه نگهداری می‌شود.

ویرایش تنظیمات، ارتباط‌های فعال **همان تونل** را قطع می‌کند. ذخیرهٔ ورودی به معنی تأیید تنظیمات و شروع هستهٔ محلی است؛ وضعیت «متصل» تنها بعد از ثبت proxy در مقصد و گزارش آن نمایش داده می‌شود. کیفیت و دسترس‌پذیری شبکهٔ واقعی دو سرور باید پس از نصب بررسی شود.

## مدیریت، پشتیبان‌گیری و بازیابی

```bash
sudo systemctl status farstar-tunnel.service
sudo journalctl -u farstar-tunnel.service -n 100
sudo systemctl restart farstar-tunnel.service
```

مسیرهای اختصاصی:

```text
/opt/farstar-tunnel/                  برنامه، venv، هسته‌های FRP
/var/lib/farstar-tunnel/state.db      وضعیت، حساب و مجوزها
/var/lib/farstar-tunnel/pki/          گواهی‌ها و کلیدهای خصوصی
/var/lib/farstar-tunnel/engines/      تنظیمات هسته‌ها (حاوی توکن)
/etc/systemd/system/farstar-tunnel.service
```

برای پشتیبان کاملِ سازگار، فقط سرویس خود برنامه را متوقف و پوشهٔ داده را ذخیره کنید. فایل پشتیبان حاوی اسرار است و باید خصوصی نگه داشته شود:

```bash
sudo systemctl stop farstar-tunnel.service
sudo tar -czf /root/farstar-private-backup.tar.gz -C /var/lib farstar-tunnel
sudo chmod 600 /root/farstar-private-backup.tar.gz
sudo systemctl start farstar-tunnel.service
```

برای بازیابی، برنامه را در همان مسیرها نصب کنید، قبل از start پوشهٔ داده را بازیابی کنید، مالکیت را به `farstar-tunnel:farstar-tunnel` بدهید و دسترسی پوشه را `0700` نگه دارید. از `init` روی دادهٔ بازیابی‌شده استفاده نکنید. هنگام انتقال سرور، IP/دامنهٔ عمومی باید با گواهی و تنظیمات نصب سازگار باشد.

اگر رمز مدیر فراموش شد:

```bash
sudo -u farstar-tunnel /opt/farstar-tunnel/venv/bin/farstar reset-password
```

گواهی سرور یک سال اعتبار دارد؛ تاریخ آن در تنظیمات پنل دیده می‌شود. پیش از انقضا آن را با همان CA تمدید و سرویس را ری‌استارت کنید (این ری‌استارت تونل‌ها را برای مدت کوتاه قطع می‌کند):

```bash
sudo -u farstar-tunnel /opt/farstar-tunnel/venv/bin/farstar renew-certificate
sudo systemctl restart farstar-tunnel.service
```

برای حذف **فقط برنامه** و نگهداری داده‌ها:

```bash
sudo bash /opt/farstar-tunnel/scripts/uninstall.sh --remove-program
```

به‌روزرسانی خودکار یا بدون وقفه در این نسخه وجود ندارد. ابتدا پشتیبان کامل بگیرید، سرویس خود برنامه را متوقف کنید، بستهٔ نسخهٔ جدید را در venv اختصاصی نصب کنید، `frp verify` و تست‌ها را اجرا کنید و بعد فقط همین سرویس را شروع کنید. نصب مجدد با `install.sh` عمداً دادهٔ قبلی را بازنویسی نمی‌کند.

## توسعه و آزمون

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python scripts/download_engine.py bin
.venv/bin/python -m pytest -q
```

روی ویندوز، از `.venv\Scripts\python.exe` استفاده کنید. آزمون‌های integration از هستهٔ **واقعی FRP** برای TCP/TLS، QUIC، WSS، UDP، اتصال دو پنل روی HTTPS، fallback، رد CA اشتباه، رد پورت اشغال، جداسازی دو تونل و لغو دسترسی استفاده می‌کنند. نبودن هسته، آزمون‌های آن را skip می‌کند؛ برای تأیید کامل ابتدا `download_engine.py` را اجرا کنید.

پیش‌نمایش محلی بدون TLS فقط روی loopback مجاز است:

```bash
.venv/bin/python -m farstar.cli --data-dir .runtime/local --bin-dir bin init --role hub --host 127.0.0.1 --port 18443
.venv/bin/python -m farstar.cli --data-dir .runtime/local --bin-dir bin serve --listen 127.0.0.1 --dev-http
```

کد راه‌اندازی را از `.runtime/local/bootstrap.token` بردارید. این حالت برای پیش‌نمایش محلی است؛ نصب سرور همیشه HTTPS استفاده می‌کند.
